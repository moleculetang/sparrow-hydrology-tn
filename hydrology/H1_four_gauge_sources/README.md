# 4站2010—2018日流量：最小来源证据与准入缺口

本补充只覆盖六陈水库（渠道）、枫树坝水库（坝下二）、南水水库（大坝）、泸江及其2010—2018资料。4站各3,287日，共13,148站日；36份最终来源CSV按原字节保存。没有发布全部水文库或2019年以后流量。

在此目录运行 `python assemble.py` 恢复10个有界分片，逐项核验129个成员原字节；随后运行 `python verify.py` 独立复核日值、日历、来源及错表用例。核验器需要pandas、numpy、pyarrow；`source_review.ipynb`提供可逐格运行的复核入口。恢复到`assets/`，遇到已有不同字节文件会拒绝覆盖，不需要旧工程绝对路径。

**来源链已找到，但4站没有获得57站敏感性分析准入。尤其泸江2018发现明确的错表配对。Q主分析使用53个共同站；53站仍只是文件数值/映射支持，不认证仪器、质控或插补真实性。** 当前H1 checkpoint实际使用的历史57站面板及冻结水文原件保留，不将本次53站分析选择冒称已经重新率定的模型。

## 原页能证明什么

2010代表性原页显示，4站均为“逐日平均流量表”，单位m³/s。CSV→A2c新增站日表→screen这条路径直接读数字，没有m³/s与cfs之间的缩放；历史月表另外保存过cfs，不能将它的换算倒灌到这些日值。公历年由原文件/来源索引登记，日期由日行/月列组合；原页未给出每日起止时刻、时区、观测频次。

| 当前站名／河段 | 原页生成方法与水量对象 | 当前代表性限制 |
|---|---|---|
| 六陈水库（渠道）／29 | 2010：“表内流量采用临时曲线法推求，主要曲线标准差2.4%。”对象为渠道断面。 | 渠道流量不等于母河道总流量或全部水库泄流；引水、分流及渠道与模型出口关系未认证。 |
| 枫树坝水库（坝下二）／47 | 2010：“表内流量为枫树坝水库逐日平均出库流量。月、年极值选自日平均值。” | 出库流量与坝下河道总流量、区间入流及具体泄水设施组成不能混用；原页未交代完整测算方法。 |
| 南水水库（大坝）／73 | 2010：“表内流量采用日发电平均出力－水头－流量关系法推求。月、年极值选自日平均值。” | 是否包含弃水、溢流及非发电出流未知。历史固定河段73与最近线/所在增量面74并存，原匹配记录完整保留。 |
| 泸江／125 | 2010为单一线法，曲线标准差5.0%；2018原页为临时曲线法、标准差2.9%—3.6%。 | 不能与严洞、东沟或“合成”系列混用。2018当前输入误配东沟。原页集水面积4497km²，历史模型站界支持2517.619km²，须查清边界/支持差异，不能按面积比修正Q。 |

这些是代表性年份的原页说明，**不将2010的方法或曲线误差扩展为所有年份认证，也不将曲线误差当成逐值仪器质控码**。原页及本地已读资料中没有定位完整年鉴题录、编制机构/封面、官方稳定站号、原始水位/测流点、率定曲线方程与适用期、发电出力/水头输入、逐值插补标志及插补真相；全部留缺。`QSUP_R029/R047/R073/R125`只是本包内部稳定映射ID；原页表序号9/3/16/24不是官方站号。

## 可核验来源链与文件

- `station_year_source_index.csv`：36个站年，原路径、SHA256、补充批次、索引站名、worker/表定位/已有OCR复核路径与哈希。
- `raw_csv/`：仅4站×9年最终权威CSV原件，来源为 `0_hydro_sediment_data/discharge/stage2_result_revised/`。36份CSV与现有同步索引哈希全部一致。
- `four_gauge_daily_lineage.parquet`：13,148行，源行/列、原token、CSV→screen数值、日期、当前河段和解析失效标志。缺测不补0。
- `upstream_extraction/`：仅选出相应站的36个原OCR worker记录，不复制同页其它站数列；全worker原路径/哈希保留。这是原文件片段导出，不冒称整文件原件。
- `table_locations/`：相应站的原定位JSON，原字节保留；`EXTRACTED_UNCHECKED`等历史状态未改名为质控合格。
- `existing_ocr_cell_review_flags.parquet`：5,429条已有OCR分歧/矩阵覆盖标志及原复核文件哈希。它们用于文字转录审核，**不是测流仪器QC、缺测插补码或独立实测证明**；没有这些标志的日期保持无记录，不补造标志。
- `station_identity_and_semantics.csv`、`historical_spatial_match_four.csv`、`four_gauge_historical_mapping_audit.parquet`：4站原名、映射、投影x/y、沿程位置、距离、已有坐标/径流支持门及原页水量对象。历史`topology_representative=True`只是该旧算法的坐标/径流支持结果，不能认证渠道/发电推算量等于全河段总Q。
- `representative_pages/`：4站2010原页，加泸江2018错配原页。照片按原字节保存；泸江原页包含相邻断面，用于区分错表，不把相邻断面加入任何站点映射或主分析。
- `historical_method/`：实际日解析、A2c源选择/新增站构建、A2h拼接/掩蔽源码，原字节保存供复核。它们是历史方法源码，不以本包目录直接重跑旧工程。
- `primary_Q_53_station_manifest.csv`：当前74站登记与有效日支持57站相交，排除这4站后的53站清单；均存在于原103站开发文件中。

独立重解析36份CSV，与A2c新增站日表、当前screen逐日数值完全一致，13,148站日键唯一、闰日一致、无跨年重复。36个相应worker导出记录也与最终CSV数值一致。**这种转录/传递一致性会完整传递上游的错表，不能证明数据正确。**

## 已保存失败用例：泸江2018误配东沟

原照片 `QSUP_R125_2018_wrong_table_evidence.jpg`（页码107）上半页为“24 泸江 泸江站”，下半页为“25 泸江 泸江(东沟)站”。当前定位JSON却把上方标题块index1与下方数据块index6配对，worker、权威CSV、A2c和screen随后一致地沿用了错表。

| 日期 | 上方泸江原页／OCR候选 | 当前泸江输入（下方东沟） |
|---|---:|---:|
| 2018-01-01 | 23.0 | 0.608 |
| 2018-02-01 | 18.0 | 0.593 |
| 2018-03-01 | 13.1 | 0.631 |
| 2018-04-01 | 21.3 | 0.370 |

独立读原Paddle layout JSON：上方泸江表有365个可解析日值，全部不同于当前输入；下方东沟初始OCR可解析321个日值，其中320个与当前输入精确一致、1个转录差异保留，其余44日在这个初始OCR片段中不可解析，未补值。当前最终worker完整365日均来自它认定为泸江的错误下方块。不能把“320精确匹配”写成原图逐格全365认证。

`lujiang_2018_wrong_table_comparison.csv`保存完整逐日对照；`lujiang_2018_original_layout_result.json`为原Paddle结果原件；`wrong_table_failure_receipt.json`保存定位与范围。上方365个OCR值只是待全原图校核的替换候选，**未写回权威CSV、screen、checkpoint或当前44条TN训练输入**，也没有用它们冒充已完成的新水文率定。

## 使用决定与待补材料

Q主分析先采用53站并明确其证据等级；57站敏感性准入仍为false。恢复57站至少要修正并逐值复核泸江2018正确断面、明确三个水库/渠道Q与模型边界的观测算子、核对南水73/74及泸江面积支持，补齐必要的来源机构/站号/方法适用期与已有插补标志。其他年份也须依原页逐年核对，不能仅凭完整数列或索引存在升级。

本次是来源/接口证据核验，NSE不适用；没有新增模拟效果成绩。冻结H1下的TN实验仍可复现，但新增错表与水量对象证据应进入最终水文证据限制，不把固定水文结果解释为已认证真实站界Q。
