## 二、与 v1 计划的核心方程差异

**v1（顺序抽取）与 v1.1（共同浓度）不是同一个核。** 逐字对照：

| 量 | v1 | 本轮（v1.1） |
|---|---|---|
| 上层抽取 | fast 先取，percolation 再从**残余**取 | 一个共同 $C_u$，$F_f$ 与 $J$ 由**分水比例**分出 |
| 代码形态 | 出现 `(A - F_f)` 参与 $J$ | **不出现**；$F_f+J=E_u$ 逐项成立 |
| 与冻结水文的序 | fast 先、percolation 后 | 与生产者相反（生产者 percolation 先于 quick runoff） |

用户裁定原文：**"在一天的尺度上，上层储量的 N 抽取不能人为规定 fast 与 percolation 的先后；
两者必须取自同一个上层浓度。"** 本轮的实现即此句：
$F_f=E_u\cdot\phi_f$、$J=E_u\cdot(1-\phi_f)$，$\phi_f=Q_f/Q_u$ 是**水量**比例，
**不是**两个浓度。因此"先后"这个概念在代码里**没有位置**。

**顺带登记一个后果**：因为 $\phi_f$ 只在两个出口之间分水、不改总量，
$\phi_f$ 的敏感性**不可能**是本轮的任何机制证据。报告不得把它读成机制。

**$g$ 的取值集未扩充**：只有 `x` 与 `-expm1(-x)` 两种拼写，本轮取 `x`（见 §四）。

## 四、推翻之一：$g$ 不是"安全默认"，而是时序闸门的确定性输出

计划 §1.3 的表有一行写着"闸门**无法判定** ⇒ 取 $1-e^{-x}$，**预注册的安全默认**，并登记"。
**本轮没有走那一行。** 闸门判定了：

* `post_outflow_carry` = `true`（导出列是**出流后的 carry**）；
* `S_pre_rebuildable` = `true`，$S_{\rm pre}$ 的重建残差 `S_pre_max_rel_residual`
  = `3.573418689577043e-14`；
* `x_le_1_globally` = `true`，`max_x` = `0.9999999999999986`，`n_x_gt_1` = 0。

三条全中 ⇒ §1.3 的**第 1 行**成立 ⇒ `closure_choice` = `"x"`，且
`is_the_registered_safe_default` = `false`。**这是判定，不是默认**，
所以事后**不允许**改成指数形。

**必须登记一件难堪的事：有两份 probe 落了两个互相冲突的 `g_decision`。**
`reports/probe_timing.json::g_decision` 写的是 `closure_choice` = `"-expm1(-x)"`；
`reports/probe_prevolume.json::g_decision` 写的是 `"x"`。**两份都在 CORPUS 里**，
所以引用 `-expm1(-x)` 这个字符串**解析得通**。

权威件是后两份：`phase0_gates.json::3.3_closure` 与 `预注册_冻结.json::closure_form`
（`"x"`，**在任何前向之前**冻结）。`probe_timing.json::timing` 已被
`phase0_gates.json::3.3_order_test.superseded` 明文列为**作废**——
它断言 $S_{\rm pre}[t]=S[t-1]$，被第四个 probe 推翻
（该错误约定的中位相对残差 `0.19099488941960677`；正确的约定是
`upper__S_post_plus_Qu_eq__S_prev_plus_recharge`，`max_rel` `3.573418689577043e-14`）。

**为什么会冲突**：`probe_timing.py` 把**出流后的**储量当分母，
于是 $x=Q_u/V$ 被人为放大到 `648546921151847.9` 量级、`frac_x_gt_1_post` = `0.2155094785061142`，
第 1 行因而不成立。这正是计划 R3′ 预言的失败模式，也正是 `probe_prevolume.py`
这个文件名（**pre**-volume）的由来。

**并须写明**：在正确的 pre 约定下，$x\le1$ **不是经验事实而是代数恒等式**——
$V_u=S_{\rm post}+Q_u\ge Q_u\Rightarrow x=Q_u/V_u\le1$ 恒成立。
所以第 1 行的第三个条件**自动**成立，闸门真正的判定内容是 **pre/post 这个约定本身**。

### 4.1 R3′ 的裁决：17.67% 的"饱和"**全部**是分母约定的伪影（比 R3′ 预言的更强）

红队 R3′ 测到"$\pi_f$ 在活跃格上约 16.45% 取 1.0"，并**要求**在时序闸门之前不得据此淘汰任何臂。
裁决结果比它预言的更强：

| 约定 | `frac(pi>=0.99)` |
|---|---|
| post（错的） | `0.17671124533908897` |
| **pre（对的、核实际用的）** | **0**（`DELTA_frac_pi_ge_0p99__pre_minus_post` = `-0.17671124533908897`） |

**而且"精确为零"是代数结论，不是数值巧合**：$x\le1\Rightarrow\pi\le1-e^{-1}$ = `0.6321`，
所以 $\pi\ge0.99$ **不可达**。浮点饱和也被排除：pre 约定下 $x>700$ 的格数占比为 0。

⇒ `N4_question_answered` 的原文是 **"NEITHER"**——$\pi=1$ 既不是浮点饱和、也不是水文学，
而是**用出流后的储量去除出流前的 $Q$**。
**并且**：这个问题**被闭包的选择溶解掉了**——取 $g(x)=x$ 时 $\pi$ **根本不被求值**，
$g_u=x_u\in(0,1]$ 是**定理**而非读数。

**一句话**：红队的**方向对，幅度也全对**（不是"一部分是伪影"，是**全部**）；
但它的后果被本轮的两个决定（pre 约定 + 线性闭包）**同时消掉**，
所以它没有资格淘汰任何臂——这与计划的规定一致。**唯一未被消掉的是 §六 那件事**：
它由同一个陷阱造成，却改变了主臂的**证据强度**。

## 五、推翻之二：惰性守卫保留——我原来的推导是错的

计划 §3.3 与 R4′ 记下了我在规划期的推导：
三同一律给出 `fast_fraction == 0 ⇔ W < 1e-6 ⇔ contact <= 0`，而
$W=Q_f+Q_p$ 在掩码上同阶 ⇒ $Q_u\to0\Rightarrow E_u\to0$，**所以不必钉掩码**，
"少一个命名自由选择"。

**Phase 0 的断言把这条推导判为假。** 实测：

| 量 | 掩码上的实测值 |
|---|---|
| `max_Qp_mm_day` | `2.5101515156966697e-14` |
| `max_Qu_mm_day` | `2.5101515156968253e-14` |
| `max_upper_water_mm` | `5.221622195298538e-28` |
| 冻结 `fast_water` 下界 | `4.184469060922251e-200` |

$Q_u$ **不在**舍入量级——它比冻结的 `fast_water` 下界高**九个数量级**；
塌下去的是**上层储量**。于是比值被推向 1：
`median_xu_unguarded` = `0.8636596200230362`，
即掩码上**中位格**在无守卫的线性闭包下会动员掉整个 legacy 池的 $86.37\%$，
且 `frac_xu_unguarded_ge_0p99` = `0.07277735618843556`。而冻结核在**恰好这些格**上
给 `max_fast_fraction` = 0。

⇒ **结论**：`decided` = 守卫**保留**，且它是掩码的**主体**而非尾部
（`frac` = `0.15477431330535965`，`n_cells` = 832141，`static_in_time` = `false`）。
**它是 N1 归约检验成立的唯一原因**，不是装饰。

**照实写**：我的推导错在把"$Q$ 小"与"$Q$ 相对 $V$ 小"当成了同一句话。
在生产者宣告水力不连通的格上，正确的读法是 **$Q/V$ 不是动员比例**——
而不是"$Q$ 小到可以忽略"。**红队的方向是对的，我的心算是错的**（红队那个
`8.209053e+09 kg` 的具体数字仍与我的实测不同，两者都不进判决）。

**守卫保留之后的三条断言（`phase0_n1.json::N2`）**：

| 断言 | 读数 |
|---|---|
| 守卫的零集**就是** `contact<=0` | `guard_zero_set_is_contact_le0` = `true` |
| 掩码上 $g_u$ **精确为零** | `gu_exactly_zero_on_mask` = `true` |
| 掩码外 $g_u$ 的上确界 | `max_gu_off_mask` = `0.9999999999999986` |

**并须更正计划的一条预期**：计划 R4′ 说"掩码上新核与冻结核在**慢路上必然不同**，
是已登记的、有意的**结构性差异**"。实测不是结构性差异：
`slow_path_agreement_kind` = **"ROUNDING (max rel 4.724e-16), not bitwise"**——
即在掩码上两者**只差舍入**。原因是守卫把 $E_u$ 精确压到 0，$J$ 随之精确为 0，
慢路只剩 $g_s$ 对 $l$ 这一点差，而两者在掩码上几乎同值
（`max_gs_on_mask` = `0.007789548659940684`）。
**"有意的结构性差异"这句话因而不成立，照实改记为"舍入级差异"**。

**同时登记一个"看起来很大、但不作判据"的数**：
`NOT_A_CRITERION_max_rel_slow_diff` = `37557.49038735743`。
它**不是**判据，因为它的分母是**冻结 $F_s\approx0$ 的掩码格**，绝大部分是 `0/0`；
把它当误差会得到一个纯粹由分母造成的巨大数字。**登记为不可用，而不是删掉。**

## 六、推翻之三：周转一致性闸门对 `V-upper` 是恒等式

计划 §2.3.2 把主臂的选定交给一个**数值**闸门：胜出者是使
$|\log(\operatorname{turnover}^{\rm cand}/\operatorname{turnover}^{\rm producer})|$
的逐河段中位数最小、且 $\le\log(1+\varepsilon_{\rm turn})$ 的候选。

**这个闸门本轮不可判，理由是两类。**

1. **对 `V-upper`，它是恒等式。** `identity_disclosure` 逐字写着：
   `86400/(100*10) == 86.4` 精确成立，所以这是**同一次除法做了两遍**，
   `median_abs_log_ratio` = 0、`worst_abs_log_ratio` = `4.440892098500625e-16`。
   `pearson` = `1.0`。**这个一致不携带任何证据。**
2. **对 `V-soil`，没有可对的列。** `soil_has_no_counterpart_column` = `true`，
   生产者只导出**恰好两列**周转：
   `upper_store_instantaneous_turnover_day` 与 `lower_store_instantaneous_turnover_day`。
   于是 `selection_by_turnover_table` = `"UNDECIDABLE (identity for V-upper; no column for V-soil)"`。

**主臂实际是由什么决定的**：`selection_by_producer_source_lines` —— 读**生产者自己的算术序**：
`hydrology_core.py:173-175` 与 `:177-180` 把 percolation、`q0`、`q1` **都送出
upper/response 储量**，而 `:170-171` 只把 `aet` 送出 soil 储量。$Q_p$ 与 $Q_f$ 正是
$g_u$ 所分的两条路，两者都离开 `fast` ⇒ `chosen` = `V-upper`，
`soil_eligibility` = 未与 $Q_f$/$Q_p$ 配对，**只作敏感性臂**。

**这算不算偏离预注册？** 严格说算**走了预注册的备用分支而非主分支**，但不构成事后挑选：

* 计划 §2.3.3 **预先**写好了"若两个都通过 ⇒ 取预注册序 `V-upper > V-soil`"，

## 七、推翻之四：P1 被恒等式证伪，主臂标 `UNIT_SCALE_LIMITED`

计划 §2.6 的 P1 要求把两个寿命分开报，并预置了证伪器：
**若 $\tau_{\rm eff}$ 与 $\tau_{\rm hydro}$ 同量级，则"M 是长期记忆"这句话在这个核里不成立**。

`P1_falsifier` = **FIRES**：比值 `0.996355630760417`（中位）/ `0.9998834994534034`（几何均值）。
`P1_verdict` = 证伪，**且不是巧合，是恒等式**：

> 在线性闭包下 `carry = (1-g_u)*s_M`，而 $1-g_u = 1-Q_u/V_u = S_{\rm post}/V_u$
> **就是保留下来的水量分数**。于是 $-\ln(\text{carry}) = -\ln(S_{\rm post}/V_u)-\ln(s_M)$，
> 而 $\ln(s_M)$ 落在 $[-0.0034,-0.00028]$，对 $O(1)$ 的水项可以忽略。

**绝对尺度比比值更要紧**：`median` = `5.392064939611057` 天、
`p90` = `8.272258836482171` 天、`max_survival_lifetime` = `9.005430363112177` 天
⇒ **N 记忆是次十年尺度的**（sub-decadal），不是长期库存。

**已按 P1 的处方执行**：`arm_label` = `UNIT_SCALE_LIMITED`，
`P1_consequence_for_the_round` 逐字写着：该臂的事件门失败**不是**
"双路径浓度结构无能力"的证据，而是"库存被以水的周转率抽干"这一**时间尺度事实**。
`P1_reproduces_phase0.ok` = `true`（`differences` 为空）——
第四节的寿命与 Phase 0 注册的是**同一批量**。

**并须登记一个被本轮作废的诊断行**：计划 §2.7 把
"$\tau_{\rm eff}\ll\tau_{\rm hydro}$"当成指向 $k_m$ 的指纹。在线性闭包下这个比值
**被钉在 1**，所以该行**在本轮不能判别**。
$k_m/k_{ex}$ 的选择必须改由 §十三 的脉冲占比与事件/月尺度的**门型**来支撑。
这是**一条预注册诊断被本轮作废**，不是被绕过。

### 14.4 冻结记录没有生产者——**绑定它，不重造它**（第 18 行）

交付收尾时按"每个证据文件都要有生产者"这条纪律回头核一遍（本谱系的教训：
`evidence-file-needs-a-producer`——只有临时命令写得出的文件**既毁得掉、也重跑不出**），
于是发现最要紧的那份反而没有：`reports\预注册_冻结.json`。

**断定方式是枚举，不是印象**：把本轮用到的**两种**写入机制都搜了一遍——
helper（`C.write_json`）与直接写（`write_text`/`json.dump`）——全部调用点是
`level_variance.json`、`phase0_gates.json`、`arms.json`、`phase1_arms.json`、
`probe_label_floor.json`、`probe_lpre.json`、`verdict.json`、`phase0_n1.json`、
`audit_dp.json`、`neighbour_write_check.json`、`prereg_freeze_check.json`（本轮新增），
**没有一处是它**。全轮只有两个 `.py` 提到它：`phase1_arms.py:665`（读）与
`check_delivery.py:108,958`（语料与引用注释）。`phase0_gates.py` 里没有
`subprocess`、没有 `runpy`、没有 `exec`，所以不可能间接写。

它**确实是**机器产出的：`recorded_at_utc` 带微秒，键按字典序、1 空格缩进
（`json.dumps(..., indent=1, sort_keys=True)` 的形制）。是**一条未留脚本的临时命令**写的。

**处置：不补生产者。** 补一个会重新写这个文件，盖上新的 `recorded_at_utc`——
那正是硬闸门①存在的理由所要防止的**事后重新冻结**。所以新文件
`work/_verify_prereg_freeze.py` **没有** `--write-record` 开关（连注释掉的都没有），
并且在起止各取一次该文件的 sha256 断言**未变**，把"我没重新冻结"这句话**自身也做成机检**。

它做的是唯一合法的修复——**绑定**：

| 绑定项 | 与之绑定的**有生产者**的产物 |
|---|---|
| `arms_table_sha256` | 用 `phase0_gates.py:466` **自己的规则**重算 `arms.json::arms` 的内容哈希；并与 `arms.json::hashes.table_sha256` 相等（`level_variance.py:119`、`phase1_arms.py:675` 断言的是同一条） |

| `n_forwards` | `phase1_arms.json::forward_count` = 5 |

**而"先于任何前向"这条，是从 mtime 证出来的，不是信它自己写的字段**——
一份**自己给自己作证**的记录不是证据：

```

预注册_判据与门槛.md  2026-09-19T17:42:25.561064Z
```

**余量 15.9 分钟**，且 `recorded_at_utc` 与该文件的 mtime 到微秒一致（临时脚本写完即盖戳）。

## 十七、不能证明的事

1. **"主臂的选定"证据强度低于计划设想**：周转闸门退化成恒等式（§六），
   主臂由生产者源码的算术序决定。这是**可复核的**依据，但**不是**一个数量闸门。
2. **水平与振幅在本轮不可分离**：本轮**没有任何水平杠杆**（`level_levers_this_round` 为空），
   所以水平失败与振幅失败**互不为证据**。主臂的水平比值 `9.143688123572442` 与
   振幅 `A_L1` = `0.7373725809958451`（**低于**冻结基线 `1.0400772083480145`）
   是**同一件事的两个侧面**，不得拆开引用。
3. **21/30 参数失效**意味着冻结参数包络对陆相**已不构成约束**——
   本轮的"零拟合"与前四轮**不同类**。
4. **月度指标只有 4 年 × 15 站**：`n_station_months` = 580、`n_eligible_rows` = 12152。
   $A_{L3}$ 是 214 事件比值的中位数，**非光滑**。
5. **`R5-ref` 与锚点不独立**：它是同一批数的第二次写法（§三）。
6. **第三路交叉不是独立测量**：路 (2) 与路 (1) 在 $x_s$ 上由 $x_s\equiv lr$ 相连（§十一）。
7. **豁免是"死"还是"活"由种子 sha 决定**：`SEEDED_COPIES` 在种子摘要不符时**返回空豁免**
   （`_seed_tokens_for` 的 `matches` = `false`），且 D39 第 5 探针证明它可撤销——
   但**它保护的是"继承来的字面量"，不是任何一句结论**。
8. **本轮不回答"双路径浓度结构行不行"**：判决 `MOBILE_POOL_MAPPING_LIMITED` 说的是
   **不能把长期 legacy 库存直接等同于 mobile N**（§七 的次十年寿命）。
   把这句话读成"双路径机制失败"**是误读**，报告不得如此写。
