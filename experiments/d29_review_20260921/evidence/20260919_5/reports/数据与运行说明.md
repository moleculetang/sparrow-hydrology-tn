## 06 重跑一个点（最小复现）

**重跑整个 $k$ 场（零前向，唯一有分片的一步）**：

```bash
cd /e/SPARROW/5_Test/20260919_5
PY=PYTHONIOENCODING=utf-8 /d/ProgramData/anaconda3/envs/sparrow/python.exe
$PY -B work/phase_minus1.py --prepare        # 写 _k_inputs.npz 与它的 manifest
$PY -B work/phase_minus1.py --shard 0/8      # 8 片各自独立；i/N
$PY -B work/phase_minus1.py --merge 8        # 按注册顺序汇编，重验 manifest
$PY -B work/phase_minus1.py --verify         # 单进程复算子集，与出货的 k 场对拍
```

**只重跑一个 (装置, β) 点的前向，用已冻结的 $k$ 场**：

```bash
$PY -B work/phase1_full.py                   # 76 点一次通过；基线共享
```

`work\phase1_full.py` **没有命令行参数**，它一次算完 `4 × 19` 个点
（这正是本轮相对 round 4 的**方法学修复**：round 4 的 Phase 2 被 Phase 1 的早期停止门控，
导致月度指标只有 `4` 个 β 有值）。若只想看一个点，
读 `reports\phase1_full.json::points["<device>|<beta>"]` ——
**键名形如 `N1e|0.5`，是"装置竖线 β"**，不是"β 下的装置字典"。

**幂等性**：`--shard` 从不调用 `main()`，`--merge` 重验 manifest，
两者都不写 `reports\` 以外的任何东西；重复跑得到逐字节相同的 `reports\k_field.json`。

逐个比较 `reports\` 里每件产物与 `work\` 里写它的脚本的 mtime，**本轮的七对全部通过**。

## 08 两项交付机检

**两项机检都是可重跑的生产者，不是一个手写的结论**：
`work\check_delivery.py reports/*.md` 逐份报告写出 `<报告名>_delivery_check.json`，
印出 `DELIVERY_CHECK_PASSED` / `DELIVERY_CHECK_FAILED`。
机检 ① 要求每一个 ≥3 位小数的字面量都能在**注册语料**里找到来源；
机检 ② 要求每一个反引号包裹的带扩展名路径都真实存在。
`FROZEN_SHA` 覆盖的 `reports\预注册_判据与门槛.md` **被显式排除**并打印其未解析引用 ——
它是冻结的预注册，不是交付声明。

### 08.1 机检的**字面量那一半曾经是空的**

修之前，`_near` 在语料含有一个 `inf` 时对**任何**有限数都返回"已解析"，

`reports\实际方法与偏离.md` 的 D39。** 下面这份读数是在修好之后跑出来的。
