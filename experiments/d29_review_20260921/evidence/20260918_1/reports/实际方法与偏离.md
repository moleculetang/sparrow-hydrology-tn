## 03 计划外的两项新增（必须登记）

计划 §3.2 只列了 `work\audit_fct8.py` 与 `work\spatial_blocks.py` 两个新增 work 脚本。
实际另加两个，理由如下：

* **`work\verify_fct8_weight.py`**：V1/V2/V3/V6/V8 **全部**从模型对象读 `phi_bar`/`mid`/`starts`，
  因此**没有一个门能看见这三者本身的缺陷**。这不是假想风险：`build_phi_bar` 用
  `np.add.reduceat(weight, starts)`，它**只有在**日轴按月连续排序时才正确，
  否则**静默给出错答案**（无异常、无形状错误）；而 δ=0 时 `phi_bar` **根本不进入**预测，
  所以任何嵌套门也看不见。该脚本用**独立路线**（显式逐月布尔掩码）重算并要求
  `reduceat` 的前置条件（月内非降连续、run 边界 == `starts`、run id == `arange`）成立。
  结果：`PASS_WEIGHT_VERIFICATION`，容差 1e-12；分组 768 月、0 个下降 run、
  边界 == starts、id == arange；两折复算差 `4.74e-16` / `4.75e-16`。
* **`scripts\bootstrap_fct8.py`**：见 §05——不修它，本轮**根本起不来**。

### 07.1 我把先验向量按参数向量切了（**同一个陷阱犯了两次**）

写成 `f.prior(t)[30:38]`，假定先验与参数向量同索引。输出显示 `delta_0`/`delta_1`

诊断：`D29_BE` 的先验长度是 **28**，**δ 块位于先验索引 28..35**。改正后 1:1 映射、
无串扰，并实测 `D29_BE prior == FCT8 prior[:28]` 逐位相同、δ 与 b 的先验尺度一致
（+1σ 均为 0.04200840）。`reports\fct8_nesting.md` §8.4 早先的"先验索引 30:38"
已在 `reports\模型与目标逐项说明.md` 中更正为 **28..35**。

### 07.2 `D_s0` 显示 PENDING，我一度判成准入缺陷

我按资源算术推出"第 4 条该放行了"，于是查了准入逻辑、事件日志、`snapshots` 预留算术、

### 07.3 `fct8_identifiability.py:87` 的归一化伪像（**登记，不重跑**）

该行用**各模型自己的** `max|fd|` 归一化相对梯度差，使

### 07.4 `validate_fct8.py` 的"完全共线"是一个空恒等式（**本轮修复并重跑**）

**这是本轮自查抓出的第二个、也是更严重的一个检查器缺陷。**

`validate_fct8.py` 的 `corr(A)` 定义是 `A @ A.T`——**返回 A 自身行的 Gram 矩阵**。
于是第 149 行

```python
xg = corr(Jz[nb:nb + nd, :nb])        # nb, nd = 30, 8
```

**静默丢掉了它的列切片**：`corr` 根本不接受第二个参数，所以这不是"δ 对基线"，
而是 **δ 对自己的自相关**，其**对角线恒为 1.0**。
这就是 `max_abs_corr_delta_to_dynamic = 1.0000000000000004` 的来历——
**一个看起来像"完美共线"的发现，实际上是一个空恒等式**。
`max_rel_delta_dynamic_correlation` 是它的重复别名，同样失效。
（对照：同一 dict 里的 `max_abs_corr_beta_b_to_dynamic = 0.6341` 与
`max_abs_corr_dynamic_within = 0.9748` 走的是 `cb[29,21:29]` / `cb[21:29,21:29]`
的**合法交叉索引**，**未受影响**。）

**真值**由 `work\fct8_identifiability.py:158-164` 用**真正的两参数** `corrmat(A,B)`
独立算出：`max_abs_pairwise_corr_delta_to_dynamic = 0.9372421233700994`，
且 δ 与 dynamic 子空间的最大主角 **12.917°**、最小主角 82.765°。

**修复**（按"artefact 复现无误 ⇒ 改检查器，不改 artefact"）：新增两参数 `corrmat`，
把该字段改为**真正的交叉相关**（对 `Jz[21:29]`），并**另加**
`max_abs_corr_delta_to_all_baseline` 保留原代码**本想**算的量；删去失效的同义字段。

**安全性**：`validate_fct8.py` **不在**冻结核清单内；它**只写**
`reports\fct8_validation.json`（第 301 行的 `w_preD29.npy` 是 `np.load`，**只读**），

### 08.5 偏离 5（须登记）：F4 已执行，并更正计划对判据量的一处命名错误

**（a）F4 的执行**。F4 是计划 §5 里最后一项既未被规则禁止（F5）、也未被前置 Gate 冻结
（F6）的工作。它在收尾之后补跑：`work\f4_gradient_decoupling.py` → `reports\f4_gradient_decoupling.json`，
**8.0 s**（单折两次 backward，无拟合、无新参数）。

执行方式是 `20260916_2\scripts\audit_gradient_information.py` 的**忠实移植**——
同一分组键（`station_key × year × month`）、同一三项分解
（`level = Σ 0.5·W·mean(res)²`、`dynamic = Σ 0.5·Σ W(res−mean)²`、`prior = 0.5‖prior(θ)‖²`）、
同一坐标（`参数 × variable_scale`）。**移植的自检**：三项之和与
`outputs\<tag>\model.json` 的 `objective` 差 **2.220e-16**（`D29_BE`）/ **8.882e-16**（`FCT8`），
即该分解**确实就是**被优化的那个目标。

结果：`cos(level, dynamic)`（scaled）由 **0.9814748185197193** 只变为 **0.9797485223024066**，
**Δ = −0.001726**。判据（计划 §6.4："若 FCT8 生效，`|cos|` 应显著下降"）**不成立**。
等价地，两梯度范数近乎相等（比 **1.016**）而余弦 **−0.980** ⇒ 水平梯度有 **80.7%**（D29_BE）
/ **79.8%**（FCT8）被动态梯度抵消。δ 块内部看着解耦（`cos = −0.631`，抵消 **10.6%**），
但其缩放后范数 **0.002605** 只有全向量的 **1/18** ⇒ **是弱耦合的小角落，不是冲突被解决**。
**详见 `专家诊断报告.md` §10.1。**

**（b）须登记的命名更正**。计划 §6.4、§5 F4 以及本轮报告早前版本，均把该判据量写作
**`cos(g_monthly, g_within)`**。**这是错的。** −0.9895 的真实出处是：

> `20260916_2\reports\gradient_information_audit.json`
> → `geometry.scaled.cosines.level_dynamic` = **`-0.9895139119787311`**

即**月水平 vs 月内动态**的余弦（坐标 `参数 × variable_scale`），
产出者 `20260916_2\scripts\audit_gradient_information.py` **从未计算**任何
"月尺度 vs 月内尺度"的余弦。**判据本身不受影响**（"解耦应使 `|cos|` 显著下降"在两种命名下同样成立），
受影响的是**引用与检索**：按 `g_monthly` / `g_within` 去查将**查不到任何产物**。

**出处唯一性已实测核对**：全工作区按字面 `0.9895` 检索，命中 21 个文件，
但其中**只有** `gradient_information_audit.json` 同时含**精确值**
（`-0.9895139119787311`）与 `level_dynamic` 一词；其余命中全是无关的数值表
（如 `20260729_46/47` 的配对统计表里写作 `0.989518`）。⇒ 本节的出处归属**无二义**。
另需注意：**按四舍五入后的 `-0.9895` 去检索，永远命不中该产物**——它存的是 16 位全精度，
不含 `0.9895` 这个子串。这正是"计划里的量名查不到东西"的第二个原因，
也是 F4 必须靠**构造**（读审计 JSON 及其产出者）而非靠**字面搜索**来定位对照量的原因。
本偏离已同步更正 `专家诊断报告.md`（§10.1、§11 #9、§12）、`简短结论.md` #7、
`模型与目标逐项说明.md` §8.3、`README.md` 欠账 #2。

**（c）可比性**（不得省略）：**−0.9895 不是本轮的读数**。它是父轮的 H0 折
（`T24_G_D`，FULL24）；本轮 `D29_BE` 臂是 H1 折（FULL24C，水文与训练集均不同），
故本轮**不声称复现 −0.9895**。F4 需要且只需要的对照，是**同一折上的 D29_BE vs FCT8**
