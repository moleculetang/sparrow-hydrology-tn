## 二、A 类：本轮自己发现并已修复的实现缺陷（A1–A6）

### A1. 台账 `loss` 少扣了导出量（实测 `6134.68 kg`，门槛 `1e-06 kg`）

**症状**：`smoke_layers25.py` 报 `ledger.local_balance_max_kg = 6134.68`
（**该试算值本身未落进语料**，此处按两位小数引用；落盘后的同一位点读数见 §A1 末的
`1.6763806343078613e-08`），而上一轮同一个量是 `7.596099749207497e-09`；N3′ 无法通过。

**原因**：我写的 `loss = (nlstar_a + pre_a) * (1 - s_M)` 把**整个** uptake 后的库都当成
未导出的陆地残留。但核由 `E_M = pre*g_u` 导出的那部分**不再**留在陆地侧；
正确的残留是 `nlstar + pre*(1-g_u)`，即 `N^{L,*} + N^{M,rem}`，再乘 `(1-s_M)`。
用错拼写时，守恒式余项的手算结果是 `pre*g_u*(s_M-1)`，与实测同阶。

**修复**：`closures_dp2.ledger_dp2` 与 `_tag_dp2_nb` 统一改为 `(nlstar + pre*(1-gu))*(1-s)`，
并把 `nlstar` **加在最后**以保持上一轮的外层结合序。
实测 **`1.6763806343078613e-08`**（与上一轮的 `7.596099749207497e-09` 同阶）。

**旁证**：诊断脚本用**同一份**核返回量重算两种拼写，错误拼写得到 `6134.68`
（= 台账报出的值，证明诊断确实复现了台账），正确拼写得到 `1.6763806343078613e-08`。
**不是猜的。**

### A2. `legacy_pool_before_transfer` 装的是**转移之后**的池

**症状**：`smoke_layers25.py` 的 N13 读数 `max_abs_dev` 非零、`is_a_single_constant = False`。

**原因**：该字段被赋成 `nlstar_a = nL - T`，即 `N^{L,*}`。于是比值量成了
`T / N^{L,*} = q_m/(1-q_m)`，与 `q_m` 的差**恰好**是常数 `q_m²/(1-q_m)`
（`q_m = 0.004987520807317687` ⇒ 残差约 `2.5×10⁻⁵`，与实测吻合到全部有效位）。

> **这个缺陷长得像一条"单一常数律"**——所以它只能靠**代数**发现，
> 靠肉眼看数字是看不出来的。这与 memory `failing-assertion-is-usually-the-assertion`
> 是同一族：**先算代数，再看数字。**

**修复**：拆分并改名。`legacy_pool_before_transfer = Ñ^L = av*rL`（转移**抽自**的池），
`legacy_pool_after_transfer = N^{L,*} = Ñ^L - T`（转移**留下**的）。
实测偏差 **`8.673617379884035e-19`**，正好是 `q_m` 的 **1 ulp**。

### A3. N13 的**断言本身**写错了：`T` 不是水的函数，但确实被状态反噬

**症状**：N13 的数据级断言 `array_equal(led_alt['transfer'], led['transfer'])`
（扰动 `V_u` 后 `T` 应逐位不变）**失败**，`n_cells_where_transfer_differs = 5369478`。

**判断**：**是断言错，不是核错。** `T` 的定义式里没有水；但 `T` 是 `Ñ^L` 的函数，
而 `Ñ^L` 是**状态**的函数：`N^M = pre*(1-g_u)*s_M` 是**被水冲走的**，所以扰动 `V_u`
会改变次日的 `uP = N^L + inp + N^M`、进而 `av`、`nL`、`T`。
**这正是本轮想要的耦合**（mobile 之后 N 就按水的节奏走），把它读成"`k_m` 依赖水"是**反的**。

**修复**：N13 数据级改判为两条：

1. **单步检验（第 0 天）**：两池初值为零 ⇒ `uL = uP = inp[0]`、`rL ≡ 1.0`、
   `nL = av[0]`、`T = q_m*av[0]`，定义式中不出现 `g_u`，且没有状态可以携带扰动。
2. **逐格律**：两份 pack 上都必须 `T == q_m * Ñ^L` **逐位**，且 `T/Ñ^L` 与 `q_m`
   的偏差 **≤ 2 ulp**。实测两份都 `transfer_is_exactly_q_m_times_the_legacy_pool = true`、
   偏差 **1 ulp**。

并把轨迹分歧**登记为"有意耦合"**：`n_cells_where_the_legacy_pool_differs = 5369550`，
注明机制与"**不是 N13 违规**"。

### A4. N12 的豁免名单漏了一个**本来就该拼** `1-exp(-x)` 的站点

**症状**：`N12.no_naive_exponential_in_source` 失败，唯一命中是 `common25.py:174`，
函数 `expm1_underlying_contrast`，文本 `1.0 - np.exp(-km)`。

**判断**：该函数**存在就是为了**测出朴素写法在 `k_m = 1e-200` 处返回 `0.0`
（计划 §3.5 N12 明文要求"本轮同时把它套在 `q_m` 上"）。它和
`dp_kernel.expm1_underflow_probe` 是同一类站点：**不写它就无法测量它是错的。**

**修复**：加入 `PERMITTED`，并把豁免理由写成**登记**（`permitted_registration` 字符串），
而不是静默放行。豁免名单因此**从 1 条变 2 条**，**两条都不在生产路径上**。

### A5. `τ_hydro` 的选择口径写错，被"与上一轮登记值对不上"**当场抓住**

**症状**：我与上一轮对锚时，`τ_hydro` 得 `4.717905371205061` d，
而上一轮登记的是 `5.411787491476153` d；`τ_eff` 也**只有 `τ_hydro` 对不上**，
`tau_eff` 反而对上了。**两个寿命里一个对、一个不对 ⇒ 不是公式错，是选择集错。**

**原因**：我把 `π = g_u` 的筛选取成了**全网格**的 `0 < π ≤ 1`。
这在数值上**恒真**（实测 `max_x = 0.9999999999999986 ≤ 1`），
所以**没有任何断言会失败**；但被 `contact<=0` 掩掉的 `832141` 个格里
`upper_water` 已塌到 `~5.2×10⁻²⁸`，`x_u → 1`，这些格把中位往下拖。
上一轮的口径是 `sel = (contact>0) & (interior)`（`interior[0]=False`，`n_sel = 4544176`）。

**修复**：拆 `pi_ok`／`pi_le1`（全网格，第二读数）／`pi_sel`（registered 选择），
用估计器 `tau_of`（`1/median(-log surv)`）把 registered 值算回来。

**佐证（逐位）**：`tau_of(1-pi_sel) = 5.411787491476153` **逐位等于**上一轮；
`tau_of(carry2[sel]) = 5.392064939611057` **逐位等于**上一轮。
**全网格读数 `4.717905371205061` 单独报出、明确标注为"第二读数，不是登记值"。**

**教训**：`0 < π ≤ 1` 这种筛子在数值上是**恒真**的，**永远是安全的、也永远不报错**；
只有"与上一轮登记的实体文件对不上"才能把它抓出来。
⇒ **对锚比对是唯一能发现恒真筛选的机制。**

### A6. 标签通道 `M` 比错了对象——**六通道里只有它一个失败，失败量级恰好等于 legacy 池**

**症状**（主臂 `P-1e2`，实测）：`source_label_sum_errors['M'] = 1.83×10⁷`，
门限 `1e-06` kg，**超了七个量级**；同一次调用的另外五个通道都在 `1e-08` 以下。

> **该试算值本身未落进语料**（它来自零前向探针），故本文按量级 **`1.83×10⁷`** 引用；
> 落盘后的同一位点读数见 `phase1_arms.json::arms/P-1e2/ledger/source_label_sum_errors/M`
> = **`2.9802322387695312e-08`**（修复后）。

**这不是舍入，是比错了对象。** 拆解（同一调用、同一格）：

| 比较 | 值 |
|---|---|
| `\|Σ_j tag_M − (ML+MM)\|` max | **`1.83×10⁷`** |
| `\|Σ_j tag_M − MM\|` max | `1.44×10⁻⁸` |
| `\|ML\|` max（legacy 池实测量级） | `1.83×10⁷` |

⇒ 标签核对的是 `MM`，而台账（也是判据）核的是 `ML+MM`，**残差就是 legacy 池本身**。

**原因**：`closures_dp2.ledger_dp2` 返回 `M = ML + MM`（陆相**状态**，正确），
而 `closures_dp2._tag_dp2_nb` 写的是 `ms[t,r,j] = MM[r,j]`（**只有一半**）。
`campaign_model.Matched.ledger` 把 tag 槽 3 映射成标签名 `'M'`，再算
`max|Σ_j tags[3] − a['M'][:, rr]|` —— 于是拿"半个状态"去核对"整个状态"。
上一轮的 `_tag_dp_nb` 写的是 `ms[t,r,j] = M[r,j]`，即**整个**保留池，
而上一轮的 `ledger_dp` 叫 `M` 的正是同一个对象 ⇒ **上一轮六通道全过**。

**这是个纯属"槽位契约"的缺陷**：槽 3 的契约是"**带标签的陆相状态**"，
本轮把它拆成两池之后，状态就是 `ML + MM`（与台账同一结合序 `ML + MM`）。

**修复（改核，不改门）**：`ms[t,r,j] = ML[r,j] + MM[r,j]`。
**没有放宽任何阈值、没有豁免任何通道**，六通道门保留全部牙齿。
修复后该通道读数 **`2.9802322387695312e-08`**。

**一次失败的诱惑与为什么不走**：另一条路是"把 `M` 通道声明为结构性不适用、只报不出门"。
**没有走**——那正是 §0.2 禁止的"事后放宽/豁免一个通道"，而且它会留下一个**名叫 `M`
的通道在门里**却不受检的隐患。**改核是把门恢复成有牙齿，改门是把牙齿拔掉。**

**归约不受影响（逐位）**：`q_m = 1` 时 `nl_star` 精确为 `0.0` ⇒ `ML[r,j] = 0.0` ⇒
`0.0 + MM == MM`（IEEE，`MM ≥ 0`）⇒ **槽 3 在父控制下的位与改前逐位相同**，
也与上一轮的 `M` 逐位相同。已**重跑** `phase0_n1.py` 证实：`tag.mobile_state`
`bitwise=True, n_diff=0, maxabs=0.0`，24 通道全过。

**为什么 Phase 0 没抓到**：`reports/phase0_gates.json::N10` **从未测过**
`source_label_sum_errors` 的**逐通道值**——它只登记了
`source_label_sum_tolerance_kg = 1e-06` 这个**门限**，没有登记任何**实测值**。
N1′ 又只做 `q_m = 1` 的逐位归约（那里 `ML = 0`，缺陷不可见）。
⇒ **这是新发现，不是回归**；也说明"继承一个门限字段"不等于"继承了那个门的实测覆盖"。

**教训**：**一个门限字段跟着台账继承下来，不等于那个门被测量过。**
`phase1_arms.ledger_gate` 会真的去算该通道，所以本轮一旦前向就会当场失败——
**被抓住是必然的，只是要花（10 次前向）才能抓住。探针把它挪到前向之前，代价是零前向。**

是**水门** `flush = 1-exp(-contact/capacity)`，与 `tau_s` 无关。
**不得把指数形式当成 `20260815_4` 的做法引用。**
