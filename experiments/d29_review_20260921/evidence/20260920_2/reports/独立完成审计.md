## 一、独立性到底"独立"在哪里（可核查的定义，不是口号）

| 断言 | 实测 |
|---|---|
| 本轮目录下解析出的模块被 import 的个数 | `imported_this_rounds_modules = []` |
| 边界口径 | "no module resolving under `E:\SPARROW\5_Test\20260920_2` is imported" |
| 唯一被 import 的冻结输入 | 事件定义（214 事件 / 15 站） |
| 为什么这不算越界 | "the 214 events / 15 stations set is a frozen **INPUT** of this round, not a statistic under audit; every reported number is re-derived here" |

**两处相对文件名被显式点名并解释**：`torch.classes`、`torch.ops`。口径逐字：

> "a relative `__file__` such as torch's _classes.py resolves against the CWD,
> which is this round's directory when the audit runs as the plan runs it;
> it is a breach **only if the file exists under this round**"

即：**判定准则是"该文件是否存在于本轮目录下"，不是名字看起来像不像**。
把这两条写出来，是为了让"零 import"这句话**可被第三方在同一个准则下复核**，
而不是要求读者相信审计者的自我声明。

**另外一处刻意的"读而不 import"**：闭包代数（`Q`/`V`/`x`/`g`/`phi_f`/`guard`）是
**冻结的、逐臂不变的**那一部分（其中**没有任何数组含 `q_m`**），审计**读**
`work/dp_kernel.py` 并按登记方程**重新拼写**，**故意不 import 它**——
因为一旦 import，它就不再是"独立重写"，而只是"同一个实现在两个进程里跑"。

### 3.1 台账的"牙齿"到底是什么（不许夸大成守恒律）

|---|---|
| 已发布的键 | `two_pool.legacy_share_of_the_land_state.at_the_final_day` |
| 值 | `0.966761667843711` |

| 后果（逐字） | "the name says 'land state' but the denominator excludes the slow layer, so the published figure **OVERSTATES** the legacy share of the whole land state by ~29 percentage points. The NUMBER reproduced exactly; **the NAME is the loose part.** No gate reads this field." |

**在审计报告里点名**，并在此处与 `简短结论.md` §1 的口径保持一致——

## 七、本条审计**能**与**不能**支撑的主张

**能支撑**：

* 本轮的两池递推、台账、`A_L1`/`A_L3` 可以被**一条不 import 本轮任何模块的路径**重算出来；
* 20 个统计量在一个**完整网格**上逐位一致（`1e-12` 容差，实测 `abs_diff = 0.0`）；
* `N13`（`k_m` 与水文无关）在独立递推上也被复现到 `8.673617379884035e-19`。

**不能支撑**：

* **不能**证明物理守恒（台账的牙齿是对**核自己的算术**的一致性，§3.1）；
* **不能**修复上一轮 `A_L1` 的缺口（上一轮的帧已发布、不可改）；
* **不能**替代判决层：`A` 改善与否由层 1 的五个门与层 2 的 F1/F2 另行判定，
  而本轮层 1 = `NO_AMPLITUDE_MECHANISM`、层 2 = `KM_MAPPING_NO_SHAPE_CAPABILITY`。
