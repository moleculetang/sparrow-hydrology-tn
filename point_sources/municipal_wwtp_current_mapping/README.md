# 污水负荷编号与当前H1河段的对应表

本补充回答PR10的两项缺口：编号与当前河段的关系，以及2020—2021独立污水负荷的可用性。按用户追加要求，实际完成污水空间映射及2006—2019历史年/月负荷重聚合，统一使用已确认的H1地理范围。**编号表及历史重聚合已完成；2020—2021独立负荷未找到，仍为未知。** 没有复制2019负荷、补零或由河流TN反推负荷。

## 编号、文件和连接方式

- `load_reach_id_to_current_h1.csv`：完整230河段的旧负荷`model_reach_id`与当前H1 `reach_id`对应。两者均从1开始；不是从0开始的数组索引。216条有向边及14个终端的编号关系与H1登记一致，终端缺下游统一表示为−1。
- `load_unit_to_current_reach.csv`：113个“旧河段×省份”汇总负荷单元，覆盖112个有历史负荷的河段。`load_unit_id=reach_编号|省份`是本次新建的明确组合键，不是原资料中的独立排口编号。可用`historical_load_reach_id, province`连接[已公开参考量](../municipal_wwtp_2006_2019/data/wwtp_reach_province_2012_tdn_anchor.parquet)；旧河段年/月量用`model_reach_id`连接。表中另存当前空间支持资格，不能只用编号相同就放行。
- `facility_id_to_current_reach.csv`：267个去重Chen厂级空间锚点的编号关系。`chen_fid`是历史产品键；`source_chen_fids`保留270个原行到267个锚点的去重关系。仅发布编号、河段、距离和资格，不含厂名、地址、组织代码或坐标。Wang匿名`wang_row_id`不能与Chen厂强配，MEE年度名录编号也不是同一个键。
- `independent_load_availability_2020_2021.csv`：230河段×2年＝460项可用性登记。`tn_load_kg_n_yr`全部为空，`availability=unknown_no_independent_product_located`，全部未启用。**这是缺项表，不是2020—2021负荷产品，也不表示排放为零。**
- `mapping_audit.json`与`manifest.json`：原产品/空间字节身份、检查口径、实际数量和文件哈希。`verify.py`直接核验公开文件，独立比较H1登记及旧汇总键；不依赖本机私有目录。
- `data/H1_*`：按213个仍在H1范围的原锚点重聚合的2012参考量、4,704条河段年量和56,448条河段月量，包含原三个溶解比例研究情景，单位kg N。质量公式和省级时间因子不变；不对域外质量再分配，也不按面积缩放。当前表只是`research_candidate_not_certified_outfall`，不是新增实测排放或自动正式启用。
- `data/outside_H1_historical_facility_loads_2006_2019.parquet`及`remapping_mass_reconciliation.csv`：17个域外锚点的714条历史厂年量、42条年/情景质量对账。每项满足“旧纳入量＝当前支持量＋域外待处理量”；未知年份仍未知。
- `remap.py`：可复用空间映射函数及命令行，调用者提供原厂级主表、H1汇水区和档案河线。公开表没有原坐标；因此此脚本不是无需原资料的坐标再计算器，`verify.py`则可直接核验本公开包。

## 空间核验及尚未解决的资格

旧污水产品依据20260810版增量汇水区。当前已确认统一支持为[20260915_2 v3／20260814图层](../../spatial/H1_unified_20260915_v3/README.md)。两套河段网络编号一致，但增量汇水区边界并不全同，不能将编号映射解释为几何一致。

本次将原Chen坐标投到H1的原等积投影，独立检查点是否落在唯一汇水区，并以原档案河线复核最近河段和距离；不根据最近距离单独认证排口。对多重边界/并列最近保留阻塞。旧质量A/B/C分别为同汇水区且距离≤2 km、2—5 km、>5 km；D为不一致。A/B/C仍只是候选位置，**不是实测排口或沿程位置认证**。

旧产品纳入的230个锚点中，**213个保持原河段候选归属；17个原归属河段16的锚点落在H1范围之外**。这17个没有强行投到最近河段，也没有从旧负荷文件删掉；只在新重聚合产品中排除并单列质量。本次完整267个锚点中26个在当前范围外、28个汇水区与最近河段不一致；原来排除的37个没有自动重新启用。含域外锚点的旧汇总单元仅河段16×Guangdong一项，原27锚点中保留10项；旧整单元标为`blocked_some_anchors_outside_H1`。其当前ID仍表示网络对应关系，不能解释为全部旧负荷已获准入河。

若以后按H1支持接入点源，须先确认这17个锚点是域外厂、坐标问题还是排口位于域内，并保存独立证据；不能按面积比缩放、移动点或沿用整单元负荷。剩余213个也仍需排放路径、实际排口/母河段及当前年份的质量证据。当前44条施肥时序路径没有启用WWTP，此补充未修改现役训练或重聚合其来源。

## 2020—2021为什么仍为空

已找到的原资料是Chen 2012空间TDN锚点、MEE 2007—2014名录及Wang 2006—2019匿名活动/氮重建资料。其官方身份见[历史方法与DOI](../municipal_wwtp_2006_2019/README.md)。本地污水资料入口、输入库、实验报告及外部数据库目录的检索没有找到2020或2021独立负荷产品；此前20260818实验合同也明确登记了2020—2022 forcing缺失。此结论不声称外部世界没有可获取资料，也不是本轮新开展了全球资料检索。

后续需要独立年度处理水量与出水TN/负荷、可靠的厂/排口身份和河段支持；仅省级总量、设施数量或推荐排放标准不足以认证逐河段实际负荷。取得资料后可按本表键建立新的年份产品，另行核验单位、排放路径、转输/终端非重叠及局地到网络质量闭合，再申请正式接入。此处没有单独WWTP拟合参数，也没有通过TN拟合填年份。

## 公开核验

在仓库根目录运行：

```bash
python point_sources/municipal_wwtp_current_mapping/verify.py
```

需要pandas、numpy、pyarrow；重新执行原坐标映射另需geopandas及其空间依赖。检查文件SHA256、唯一键、全部230编号与H1边/面积、267锚点去重关系、213/17资格、113负荷单元连接，以及460个缺项为空且未启用。独立以新参考量及原省级因子复算全部年/月质量，核验新旧产品和域外质量闭合，沿用1e-6 kg容差。空间/资料验收的NSE不适用；不宣称新增真实水质预测收益。第三方资料沿用原提供方条款。

此次统一的是污水产品的空间支持，不代表后续S1土地、农业、沉降等全部输入已同步重聚合完成。当前训练仍保留原身份；不能把此公开补充描述为现役全链输入已经统一。
