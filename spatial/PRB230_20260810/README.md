# 后续新 S1 来源采用的空间支路：20260810 修正几何

**这不是此前已经统一的 H1／旧水质空间基准。** 原统一基准见 [20260915 v3](../H1_unified_20260915_v3/README.md)，使用 `20260814_1/inputs/spatial/reach_catchments.shp`。本目录保存后续新 S1 来源处理实际引用的 `20260810_1/inputs/spatial_corrected/reach_catchments.shp`，用于追溯两套输入支路的分叉。完整 SHP、SHX、DBF、PRJ、CPG 原始字节保存在 `vectors/reach_catchments.zip`，解压到当前 vectors 目录即可使用；河段、外边界及小组件直接提供。

这是一份项目内部冻结的、可追溯的计算基准。它不代表已经取得权威独立汇水区真值，也不代表 H1 与来源面积已完全统一。

## 文件与职责

| 文件 | 内容与用法 |
|---|---|
| `vectors/reach_catchments.*` | 230 个**增量**汇水区，`reach_id=1…230`；对局地降雨、土地和外源进行空间积分。不要将上游累计面积当增量面积再次入账。 |
| `vectors/reaches_topology.*` | 同一修正版本的 230 条河段及属性；以 `reach_id` 连接汇水区。几何邻近不能替代下游拓扑。 |
| `vectors/prb_boundary.*` | 重建时使用的流域外边界，原生 EPSG:4326；在投影转换后与增量汇水区并集核对。它不是某个水质站的汇水范围。 |
| `tables/topology_edges.csv` | 230 河段的原修正拓扑与增量／累计面积字段。216 条下游边、14 个终端和弱连通分量、无环。 |
| `tables/topology_correction_contract.csv` | 五条新增连接 `14→19`、`64→59`、`132→149`、`180→168`、`199→196` 的坐标及证据。 |
| `tables/H1_FULL24C_topology.json` | 当前训练实际读取的冻结 H1/FULL24C 拓扑；其下游边使用**零起始索引**。QA 将其转为 `reach_id=索引+1` 后验证与修正图一致。内部汇入口／接触份额等额外职责不能用线端点替代。 |
| `tables/geometry_H1_area_crosswalk.csv` | 逐河段几何面积与冻结 H1 有效面积对账；两种面积分别保存，不通过比例改写水量或源质量。 |
| `evidence/corrected_topology_validation_20260810.json` | 原空间重建验收回执的原始副本，包含当时运行身份。 |
| `evidence/spatial_validation.json` | 本次公开副本的哈希、几何、拓扑、外边界和 H1 面积独立回读。 |
| `evidence/prb_boundary_original_metadata.xml` | 外边界原始历史 XML 的原样档案。它含陈旧的 Clarke 1866／零要素描述，与当前 PRJ 和实际要素不一致；不作为当前 CRS 的依据，也不放在自动关联的 SHP 旁。 |
| `manifest.json`、`verify.py` | 文件来源、大小与 SHA256；下载后可核验全部发布文件及几何／网络数量。 |

`reach_catchments` 和 `reaches_topology` 使用 WGS84 基准下的自定义 Albers 等积投影，单位为米：中央经线 109.06625°、纬度原点 24.55625°、标准纬线 22.25°／26.87°、假东距和假北距均为零。**不要因 WKT 显示 `unknown` 就将图层强行指定为 EPSG:4326。** 完整 WKT 随 PRJ 和验证回执保存。SHP 的全部配套文件应保留相同文件名前缀；CPG 指定 UTF-8。

外边界的 EPSG:4326 是当前 PRJ 及实际生产读取所采用的身份，不是对陈旧 XML 所述原始测绘基准的重新认证。原 XML 已在本地原样保留，不随公开包发布；本 PR 没有因它的旧描述转换坐标或修改冻结边界。

## “统一”已经完成和仍未完成的部分

已确认的几何总面积为 **414,345.6372136284 km²**，全部 230 河段面积为正，河段间面积大于 1 m² 的重叠对为零。其并集与重建所用流域外边界闭合。最初 D8 划分覆盖 99.160242%；132 个未分配组件按最近汇水区启发式补齐，因此不能把接近 100% 的覆盖率解释成边界已由独立实测认证。

冻结 H1 的有效面积合计 **410,866.1378872674 km²**，较几何少 **3,479.4993263610 km²**。9 河段相对差超过 1%：16、43、92、111、116、122、123、130、230。这是已登记的空间支持限制。本 PR 不替换 H1 面积分母、不缩放氮量、不重新生成水文，也不把问题登记为已解决。原有审计指出约 35 个站的上游支持包含这些异常河段；该站点数量属于 2026-09-26 的审计人口，不由本空间文件包重新认证。

因此，本轮准确表述是：**此前 H1 与旧水质已经在 20260915_2 v3 统一；后续新来源聚合又引用了另一套几何，重新引入空间支持不一致。** 不能把这种输入版本回归说成用户没有做过统一，也不能只凭面积比把氮量或水量缩放回去。当前冻结训练未热改；后续输入修复应回到已确认支持，重新聚合并验收所有受影响产品，另登记科学身份。

## 与旧文件、站界的区别

`0_reach_topology/results/vectors/reach_catchments.shp` 是另一套旧生产几何，不能因为文件名相同而覆盖本版本。后续若文件重建，先比较完整组件的 SHA256，再判断是否仍属于同一空间身份。

此包不将 `PRB水文站_全部.shp` 中的旧水文站人口冒充当前 116 个认证月度水质站。模型站界使用冻结 OU 支持：上游集合和母河段沿程份额共同决定水量、质量与浓度读出；母河段出口不能自动代替站界。当前水质模型的 116 月站、15 合格 HF 站与 230 模拟河段分别是不同人口，230 河段不等于 230 个已验证水质站。

原裁定依据：`20260810_1/README.md` 与 `reports/spatial_correction/corrected_topology_validation.json`；后续采用和限制依据：`20260925_1/outputs/deposition_reach/README.md`、`20260926_1/reports/水质输入空间拓扑与产品验收_20260926.md` 及其 `outputs/spatial_topology/audit_receipt.json`。本次回执核对该审计的 catchment SHA256 `792f8138935ae06ce7730435b406c3f4900516fb2c03e73eff31283eff5476cf` 与实际发布的 SHP 一致。

## 复核

在具有 GeoPandas、NumPy、Pandas 和 NetworkX 的环境中运行：

```bash
python spatial/PRB230_20260810/verify.py
```

默认先核对全部组件字节，再核对 230 唯一 ID、正面积、投影、216 条无环边及 H1 同边集合。本包不含 TN 标签、驱动数组、检查点或密钥；本次新增公开的空间资产是用户明确授权的 SHP 配套文件和空间对账。空间 QA 的 NSE 不适用，不能由此推断水质预测改善。现役训练和科学合同未改变。
