# 专家可直接拟合的 TN 小流域挑战包

这是最新版 M0 / SC 灰箱的真实数据子集：**39个河段、17个主评价站、4座水库，1961—2024完整逐日驱动，2016—2024月TN**。不需要原作者机器上的缓存、绝对路径或 pickle 数据。模型的 M 矿质氮 legacy、L 慢水氮、河道及水库状态保留，所有参数点评估均从1961年零初始状态连续演化。水文与S1源冻结，拟合只作用于全域共享参数。

请先读 [为什么多轮实验仍未取得可靠预测收益](../WHY_MANY_ROUNDS_FAILED.md)，再运行本目录。最新原始专家报告和实际方法报告在 [evidence/20260911_1](../evidence/20260911_1)。原实验仍是科学阴性结果；本包的发布不改变该结论。

## 为什么选择这一段数据

不是截取几个容易拟合的月份，而是取两个**完整上游连通分量**：北江终端reach56（22河段、12主评价站、1水库）与东江终端reach22（17河段、5主评价站、3水库）。选取依据为拓扑完整性、训练期覆盖、流域对照和水库差异，没有按2023/2024的收益挑样本。保存全历史可避免省略上游质量、截断预热或重置legacy。

这组样本能暴露当前模型的低相关、幅度及峰值偏差，并包含不同上游汇流与水库条件。但它是目的性选择，不是全域的概率样本，也不覆盖所有氮源组合、230河段的环境范围、多控制河段水库和坝下观测算子。训练TN第50/90/99百分位为1.76/3.018/4.183 mg/L，全域同期为1.86/3.775/6.719 mg/L，故本包明显欠覆盖高浓度尾部（详见validation分布表）。主评价17站均为普通河段内站；水库在上游参与输移。棉江40.30667 mg/L极端值不在此包中。**拟合好本包是值得继续全域检验的证据，不能保证全部站点都能拟合好。**

完整保留18站1,504条原记录，其中白盆珠站108条沿用既有“位置未解决”排除，主评价为17站1,396条。不得把这108条直接归入主结果。

| 文件 | 年份 | 记录数 | 站数 | 用途 |
|---|---|---:|---:|---|
| data/train.csv | 2021—2022 | 393 | 17 | 默认拟合 |
| data/development.csv | 2023 | 164 | 17 | 开发诊断 |
| data/evaluation.csv | 2024 | 164 | 17 | 冻结方案后评价 |
| data/hindcast.csv | 2016—2020 | 675 | 12 | 本轮拟合未用的时间外回报 |

2023、2024分别只有12/17站满足至少8条记录且观测方差为正的动态指标条件；其余站仍报告RMSE/偏差。全部年份曾被项目查看，且本次数据公开，因此不是盲测。刻意不附2025，以免将水文延伸/氮源沿用与本次小流域试验混合。

## 直接运行

在仓库根目录执行。已有 `sparrow` 环境就继续使用；新机器可用 `conda env create -f expert/tn_challenge/environment.yml` 创建。实际测试依赖版本见 `validation/original_parity.json`；CPU float64，每进程一线程，不要求GPU。

```powershell
conda --no-plugins run -n sparrow python expert/tn_challenge/verify.py
conda --no-plugins run -n sparrow python expert/tn_challenge/run.py fit --variant M0 --start 0 --max-calls 1000 --seconds 3600 --out expert/tn_challenge/runs/m0_0
conda --no-plugins run -n sparrow python expert/tn_challenge/run.py fit --variant SC --start 0 --max-calls 1000 --seconds 3600 --out expert/tn_challenge/runs/sc_0
conda --no-plugins run -n sparrow python expert/tn_challenge/run.py evaluate --model expert/tn_challenge/runs/sc_0/model.json --labels expert/tn_challenge/data/development.csv --out expert/tn_challenge/runs/sc_0_development
```

方案、先验、预算冻结后，另用 `evaluation.csv` 和 `hindcast.csv` 评价。只想产生预测，可用 `predict --model ... --metadata .../evaluation_metadata.csv --out ...`。`Predictor` 不接受 `tn_mg_l`；默认fit只打开指定训练标签。其余标签虽然公开，也不得用于调参后还称独立验证。

训练写出最低合法目标检查点、最终模型、每次完整调用轨迹和逐条RAW权重；预算用完会如实标记数值未充分。输出目录必须是新目录，避免覆盖。评价写出逐条预测、逐站统计、逐日物理账本和守恒摘要。旧的 `reference_only` 不会被fit读取。

**这里提供的是简洁的、带解析梯度的缩放 L-BFGS-B 专家起步脚本，不是原注册 TRF＋精修流程的复制。** 它用于让专家接上自己的求解器。原流程源码已在本PR的 `5_Test/20260911_1/scripts/sc_worker.py`、`fc_solvers.py` 等文件中。本包没有宣称换优化器能解决结构问题，也没有为发布重做正式训练。一次SC新鲜起点烟测完成12次完整调用、约3.64秒（目标调用阶段；不含环境与导入），按预算结束，投影梯度0.644，**未收敛**。不能把烟测目标或预测当成新研究成绩。

专家可直接使用 `Objective(data, train, 'SC').value_gradient(theta)` 接入其他有界求解器；`names`、`bounds`、`initial(0/1)`、`variable_scale()` 均公开。本包默认SC从原preset加零系数开始；原八路径实验中的“本折最佳M0加零扩展”调度仍见原方法报告，不混称相同训练方案。所有科学改动请单独记录，不覆盖M0/SC参照。

若并行跑自定试验，每worker一线程；按实测峰值分配，CPU或RAM达到90%停止派发、RAM90%退让、低于85%恢复。本小脚本本身不提供后台并行调度、续算控制器或定时任务；默认只跑一个有时间/调用预算的进程并保留最低目标点。注册实验的后台调度与该起步脚本是不同层次。

## 方程与目标保持什么

21参数M0：共享接触率和寿命环境映射、接触指数、河道损失、上层水/渗漏调制、快慢分配；SC新增6个共享系数。静态属性使用本训练站对应河段的1/99分位裁剪与标准化；动态尺度只由训练年份/河段确定。RAW权重为 `1/(站数×本站记录数×max(本站总体方差,训练方差下限))`；下限为至少12条且正方差训练站的第10百分位。先验与原实现相同，并除以训练站数。**在17站重拟合时，先验项归一化与116站全域拟合不同；必须同一子集内比较，不能直接横比目标数值。**

SC保留 `A=M_previous+input−actual_uptake`、训练前preset0可用库存中位数S及其1kg下限、`z=(A−S)/(A+S)`、`P2=(3z²−1)/2`、当日湿润度W相对前30日均值的δ，六项 `z,P2,zδ,P2δ,zWδ,P2Wδ`。风险倍率为 `exp(log4*tanh(c·B/log4))`；零系数恢复M0，c界[-1,1]、先验SD=0.25/√6。导数包含A及完整M/L历史反馈。源和摄取需求仍按原月首脉冲注入/申请，实际摄取不超过可用量；本包没有偷偷平滑源输入。

`sc_kernel.py` 与最新原核字节一致。`routing.py` 提取原路由及其反向导数，仅把两个硬编码230的维度改为输入河段数。`model.py` 是去除旧绝对路径后的参数/输入适配器。验证证据：同参数完整子流域预测与原230河段模型最大差异 M0 1.33e-15、SC 1.11e-15 mg/L；27参数完整历史差分最大归一误差1.27e-8；同样本RAW+MAP与旧实现目标差1.42e-14、梯度最大差2.47e-13。另核对守恒、零扩展、训练/评价ID隔离、未来驱动不改变过去预测。数值容差不是实际氮库存准确性的证据。

## 专家最值得检验的问题

1. 从预设冷起点出发，在相同RAW数据项下，先改善训练站的动态响应，而不只是减少先验罚项；同时报告D、R、J和原坐标投影梯度。
2. 输出A/S和响应函数在**实际经过的状态**上的形状。全域SC中位A/S约149/171，库存基函数接近平坦；不能只画A/S≤10的漂亮响应曲面。
3. 逐站检查峰值缺口、误差相位与源/摄取月首脉冲、快慢路及入河前后传递之间的关系。守恒、摄取上限通过，不等于真实机理已识别。
4. 如果本包改善，固定方程、预处理策略与调参规则后，再检验2024、早期回报，随后才讨论全域。可额外预先注册只训练北江、预测东江的空间对照，但必须重新创建仅北江训练的尺度/方差/S；不能使用全17站训练后的参数称空间验证。

请交回代码差异、精确训练ID/哈希、初始化、参数/先验、预算、训练轨迹、所有原始留出逐站结果和物理账本。若需局地站点历史TN或自由日E才能达到很高NSE，记录为条件拟合能力，不当作可迁移灰箱预测。

## 数据质量与参照

见 [DATA_DICTIONARY.md](DATA_DICTIONARY.md)、`data/quality.json`、`data/coverage.csv`、`data/provenance.json` 和 `data/manifest.json`。无重复站月、无缺失/负TN不意味着原始观测已核实：全部1,504行只有月份，聚合定义未核实；769行缺原表行关联，735行原站CSV未登记。训练MAD敏感性标记仅1/393条，原值和RAW权重均未改动。

`reference_only` 保存**用全部116站2021—2022标签拟合**的原F23参数及本子集逐条预测。它用于复现失败模式/验证适配器，不是小样本冷启动成果，也不可作为独立空间验证起点。该SC在本子集训练NSE中位−1.3596/r=0.0153，2023为−2.2348/−0.3963、2024为−3.8680/−0.2911（动态12/17站）；说明本包保留了困难案例。与主报告不同是队列不同，不是数据矛盾。
